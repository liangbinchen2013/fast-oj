# fast-oj

**在线演示：<https://oj.lbcoj.top/>**

大量异常访问和批量注册会被封 IP（整站 403，按地址或网段，见[IP 封禁](#ip-封禁与按地址流量)）。

超级无敌简洁的 OJ，UI 极少。**只有网页**：人是唯一的使用者，出题、用例、判题、私信、后台全在浏览器里点。

- 单个可执行文件，零外部服务依赖（SQLite 内嵌，纯 Go 驱动）
- 判机与服务器分离，判机只需要一个出站 HTTP 连接（那是判机的内部协议，网页上没有入口）
- 题面、动态、个人简介、首页语统一走 Markdown + KaTeX 数学公式
- 首页内容（站名、首页语、友情链接、页脚、页脚 API 提示、注册开关、发信配置）在网页后台改，不用重启
- 页面每次请求的处理时间在 0.2–3 ms 之间（200 题 / 500 提交规模，见[性能](#性能)）

## 30 秒跑起来

### Ubuntu / Debian：一条命令

```bash
./run.sh
```

四件事：确认 `go` 和 `g++`（缺了就告诉你 apt 装什么）、编译到 `dist/`、按 `127.0.0.1:8080` 起服务器并顺手带起一台判机、Ctrl-C 时两个一起收掉（不留孤儿判机空轮询）。两个令牌没给就随机生成并打印出来，想固定下来就 `export FASTOJ_ADMIN_TOKEN FASTOJ_JUDGE_TOKEN`——脚本里写死一对默认值迟早跟着仓库传到网上。

```bash
FASTOJ_ADDR=0.0.0.0:8080 ./run.sh   # 同网段都能访问（判机仍然走 127.0.0.1 连它）
JUDGE=0 ./run.sh                    # 只起服务器，判机在另一台机器上
./run.sh -no-register -v            # 其余参数原样传给服务器
FASTOJ_DATA=/srv/fast-oj/data ./run.sh
```

端口上已经有一个 fast-oj 在跑时它会拒绝启动并提示换地址，不会留下一个"看起来起来了但其实没起来"的服务器。

### Windows，或想手动分两步

```powershell
powershell -File build.ps1        # 产出 dist\fast-oj.exe dist\fast-judge.exe
```

```bash
# 1. 服务端（两个令牌必填，留空会拒绝启动）
./dist/fast-oj.exe -addr 127.0.0.1:8080 -data data -admin-token ADM -judge-token JDG

# 2. 判机端（需要 g++ 在 PATH 上，可以和服务器同机；要收 Python 就再装一个 python3）
./dist/fast-judge.exe -server http://127.0.0.1:8080 -token JDG -name box1 -v
```

**Linux 上不要把令牌写在命令行上**：`-token` / `-admin-token` / `-judge-token` 在 Linux 会直接拒绝启动，
只认环境变量 `FASTOJ_JUDGE_TOKEN` / `FASTOJ_ADMIN_TOKEN`。原因是 `/proc/<pid>/cmdline` 是 0444、
所有本地账号都读得到（`hidepid` 默认没开），而判机上跑的正是别人提交的代码——写在 argv 里的令牌
等于发给整台机器，一次逃逸出沙盒的运行就能把它抄走。systemd 里 `-token $FASTOJ_JUDGE_TOKEN` 这种写法
也是同一个问题：`ExecStart` 会先展开再 exec，0600 的 `EnvironmentFile` 就白设了——正确做法是让
`ExecStart` 里不出现令牌，进程自己去读那个文件提供的环境变量。Windows 开发机没有 `/proc`、单机一个人用，
所以只警告不拦。

浏览器打开 <http://127.0.0.1:8080>。**全新库的第一步**：打开 <http://127.0.0.1:8080/admin/claim>，把 `-admin-token` 的值填进去，给 `admin` 账号设一个网页密码，之后就是普通登录（这个页面在旧库上也能用，属于恢复手段，会先警告你要覆盖已有密码）。命令行只留一件事——探活：

```bash
curl -s localhost:8080/healthz          # ok
```

运行概览（版本、数据目录、WAL、各项计数、页面清单）现在是网页 `/about`，判机在线情况是网页 `/judges`。

## 没有对外 API

以前同一个 URL 会按 `Accept` 与 `?format=` 给浏览器 HTML、给 curl 纯文本、给脚本 JSON，还有「用户 API 令牌」让脚本代替人提交。这套全部撤掉了：

| 撤掉 | 换成 |
|------|------|
| `?format=json` / `?format=text` / `Accept` 协商 | 每个页面只出 HTML |
| 用户 API 令牌（`/settings` 签发、`/account`、`/whoami`） | 浏览器会话，`tokens` 表已删 |
| `POST /submissions`（脚本提交代码） | 题面页的提交表单 |
| `POST` / `PUT` / `DELETE /problems`（JSON 建题改题） | 网页出题：`/problems/new`、`/problems/{pid}/edit` |
| `POST` / `DELETE /problems/{pid}/cases`（JSON + zip 清单） | 网页用例管理：逐条增删改，zip 只做批量导入 |
| `GET` / `POST /users`、`POST /users/{handle}/tokens` | 注册页 + `/admin/perms` 权限控制台 |
| `?wait=秒` 长轮询 | 提交详情页判题中每 2 秒自动刷新 |

保留的两处不是给人用的：`/healthz`（一行 `ok`，给 Docker / 反代探活）和 `/judge/*`（判机协议，只有判机令牌能访问，网页里没有任何入口）。少了一套视图就少一条代码路径：页面和权限判定从此只有一条，浏览器不会比谁多看到一点东西。

网页版页面：首页 `/`（站名 + 首页语 + 统计 + 最新题目 + 动态 + 打卡）、题库 `/problems`、题面 `/problems/{pid}`、出题 `/problems/new`、改题 `/problems/{pid}/edit`、用例 `/problems/{pid}/cases`、动态 `/feed`、提交列表 `/submissions`、提交详情 `/submissions/{id}`、排行榜 `/rank`、个人主页 `/u/{handle}`、关注与粉丝 `/u/{handle}/following` `/followers`、私信 `/messages`、登录注册 `/login` `/register`、设置 `/settings`、站点设置 `/admin/site`、权限控制台 `/admin/perms`、安全审计 `/admin/audit`、判机 `/judges`、运行概览 `/about`。

## 题面写作（Markdown + KaTeX）

题面按 Markdown 渲染，支持标题、表格、围栏代码块、列表、引用、链接。

数学公式：

- 行内用 `$a + b$`
- 行间用 `$$ \frac{a+b}{2} $$`，**并且要让这一段只放公式**：`$$…$$` 夹在句子里会被读成两个相邻的行内 `$…$`，结果是公式渲染了、两侧各留下一个裸 `$`。行间公式请单独占一行（前后空行最稳）。

渲染器把两者输出成 `<span class="math inline">\(…\)</span>` / `<span class="math display">\[…\]</span>`，页面里的 `math.js` 只对这两个节点调用 KaTeX，所以代码块里的下划线、`$` 不会被误当成公式。KaTeX 走 CDN（jsdelivr，0.16.11），但**只有页面上真的出现公式时才会去取**（模板里没有 CDN 标签，`static/math.js` 发现 `span.math` 才注入）；**CDN 不可达时公式退回显示原始 TeX**，题面照样能读。需要完全离线就把 KaTeX 与字体嵌进二进制，见[性能](#浏览器侧的账f12-限速-3g)。

> 注意：请写 `$…$`，不要写 `\(…\)` —— 后者会被当成普通文本并吞掉反斜杠。

安全边界（题面也是不可信输入）：

- 裸 HTML 一律丢弃（`SkipHTML`），`<script>`、`<img onerror=…>` 进不去
- `javascript:` / `data:` / `vbscript:` / `file:` / `blob:` / `about:` 链接被拒（`Safelink` + 白名单谓词）
- 外链自动加 `target="_blank" rel="nofollow"`

同一条流水线也用在动态正文、个人简介、首页语与页脚上 —— 这些同样是用户/操作员输入的不可信文本，规则一模一样。

## 首页、站点设置与动态

`/admin/site`（需要 `site.settings` 权限）改的是数据库里的站点配置，不是启动参数：

| 项 | 说明 |
|----|------|
| 站点标题 | 标签页、导航栏与首页大标题 |
| 首页语 | 首页大标题下面那段，支持 Markdown + 公式 |
| 友情链接 | 每行一条 `标题 \| https://…`，最多 20 条，只允许 http/https/mailto |
| 页脚 | 可选，全站显示 |
| 页脚 API 提示 | 默认**空**（纯文本 API 与 `?format=json` 已经撤掉，页脚不再宣传不存在的入口）。填了就显示，支持 Markdown |
| 允许自助注册 | 与 `-no-register` 取与；关掉后 `/register` 的页面与 POST 都是 403 |
| 允许发动态 | 关掉后 `POST /feed` 一律 403，动态页与首页把输入框换成一句原因；已发出去的照旧能看 |
| 允许发帖与评论 | 关掉后发帖与评论都停，读帖照旧 |
| 允许建比赛、加入比赛与赛内提交 | 三个入口一起停：只挡建赛与加入的话，名单里的人还能继续交 |
| 允许发私信 | 关掉后对话页把输入框换成一句原因；历史消息照旧能读 |
| 注册需要验证邮箱 | 第六个开关，方向和前五个相反：它不是"不再收新的"，而是"新来的先把邮箱证明清楚"。勾上后新注册的账号是未验证的，能登录能读，但不能提交代码、不能加入比赛；**默认关**，只有显式勾上才生效（见下面「邮箱验证」） |

五个功能开关都**只在显式写 `0` 时关闭**：缺行或写坏一行不会把整个站点锁在外面。关掉不等于删掉——
已发布的内容、历史成绩、这些页面本身全都还读得到，开关管的只是"不再收新的"。学校站考试周
把动态、帖子、私信关掉，只留题目和比赛，就是这个用法的来由。

保存是一次事务，页面缓存 2 秒后自动过期，改完刷新即见。被拒的保存会把已填内容原样留在表单里（长度按字符数算，与浏览器 `maxlength` 一致），不会让操作员整页重打。

### 每个人自己的配色（`/settings` 的「配色」那张卡）

站点设置的标题、页脚那些是**全站**的；配色这一张是**每个人自己的**：`/settings` 里九个取色器
加一个明暗底色三选（跟随系统 / 固定浅色 / 固定深色），保存后立刻生效，而且只对登录着的这个人
生效——同一条题目链接，两个人打开是两种样子。没登录的人看到的是站点默认。

能调的就是这九个槽位，对应 `style.css` 里那组变量：背景、正文、强调、次要文字、分隔线、代码底色、
通过、失败、警告。

- **为什么不是"随便写一段 CSS"**：这一串文本会进 `<html style="…">`，那是 **CSS 上下文**而不是
  HTML 上下文——放开成任意样式，等于任何人都能改写这台站点的页面（挂个外链、遮掉导航栏、把别人的
  题目盖住）。所以键名固定九个，值只认 `#rgb` / `#rrggbb`，其余一律整条丢掉
- **脏数据两头都挡**：写入前校验一次，渲染时再校验一次。库里被手工塞进 `}`、`url(...)`、
  `expression` 之类的东西，只会让那一格静默失效，拼不出第二条规则
- **为什么快**：配色存在 `users.theme` 一列里，跟着 `authenticate` 本来就要读的那一行一起出来
  ——**每次渲染不多一次查询**。代价是解析那串文本：`BenchmarkParseTheme` / `BenchmarkThemeStyle`
  两条微基准实测九键解析 2.3 µs、拼串 0.9 µs（Windows 上抖动在一倍以内，量级就是微秒）；带满九格
  配色的人与什么都没调的人，首页 400 次渲染的均值分别是 3.41 ms 与 3.23 ms（同一台机器、同一份库，
  差值落在噪声里）
- **没调过的人零变化**：一个属性都不写，`<html>` 与这个功能不存在时逐字相同，也就谈不上"新代码
  拖慢了老页面"
- 取色器是原生 `<input type=color>`，**没有为此加过一行 JS，也没有外部依赖**；`themeDefaults`
  那张表镜像 `style.css` 的两套调色板，改样式时要同步它，否则取色器给出的初值是旧的（写错的后果
  只是初值不准，不会渲染出错）
- 注销账号时这一列跟着被抹掉：观感属于身份，不属于留下的那些记录

### 发信配置（SMTP）

同一页往下就是发信配置：服务器地址、端口、用户名、密码、发件地址、加密方式，
存在 `site_settings` 里（`smtp.host` / `smtp.port` / `smtp.username` / `smtp.password` /
`smtp.from` / `smtp.tls`），跟首页文案一起保存、一起生效，不用重启也不用改启动参数。

- **密码是只写的**：这一栏永远渲染成空框，页面上只有 `••••••（已保存，输入新值以替换）`
  这样一句占位提示，明文从来不回页面、也从来不进日志。**留空保存 = 沿用已存的那条**
  （否则改一句首页语就把密码洗掉了），要换就输新值。
- **「发送测试邮件」是 `POST /admin/site/test-email`**，用的是表单里**刚填的**值，不用先保存。
  失败时把服务器/系统回的原话贴在页面上（`535 5.7.8 …`、`连不上 smtp.example.com:587 …`），
  而不是转成一句"发送失败"——照着那句话改就行。结果**不走跳转**：报错里带着地址与用户名，
  不该被地址栏、referer 和访问日志各留一份副本。
- 加密方式三选一：`starttls`（587 的默认）、`ssl`（465，连上就是加密的）、`none`。
  这一项要人自己说清楚，因为 587/465 选错的表现是转一分钟然后超时，不是一条错误信息。
- 两个超时是写死的：连接 8 秒、整封邮件 25 秒。一台连不上的邮件服务不该把后台请求挂成浏览器上转圈的那一分钟。
- 库里没填的项会退回去读环境变量 `FASTOJ_SMTP_HOST` / `_PORT` / `_USERNAME` / `_PASSWORD` /
  `_FROM` / `_TLS`（**库里有值的赢**，逐项判断），给"密码只从部署环境注入"的用法留着。
  本次改动之前本仓库没有任何邮件相关的 flag 或环境变量，所以这条兜底是新增的，不是从旧配置继承的。
- 勾「注册需要验证邮箱」但没填服务器/发件地址会被拒保存：那个组合的结果是新注册的人
  收不到信、又被闸门拦住，正是这一页要避免的局面。

### 邮箱验证

开关一开，注册流程变成：建号（`email_verified=0`）→ 寄一封信 → 人点链接 → `GET /verify?token=…`
把账号标成已验证。

- **闸门只管两件花钱的事**：`POST /problems/{key}/submit`（包括比赛页与赛内页的提交，
  所有交代码的路都汇到 `createSubmission` 这一个函数）与 `POST /contests/{key}/join`。
  登录、题库、题面、动态、帖子、比赛页面、私信、打卡全都照旧——读不花钱，写才花，
  而且一个读不到题面的人也不会想去验证邮箱。
- 未验证时题面页**不出现提交框**，出现的是原因和一个去处；写路径给同一句话。这是
  「被禁止发动态」那套写法：页面和闸门问的是同一个问题，所以不会出现"框在、一交就 403"。
- 令牌**只用一次**：库里存的是它的 SHA-256，`used_at` 一写就永久作废；第二次点同一个链接
  得到的是「这个链接用过了」，过期的得到「已过期，请重新发送」。链接上还记着收件地址，
  验证时要求它和账号现在的邮箱一致。
- **重新发送**在设置页（`POST /settings/email/resend`），只有未验证的人看得到这颗按钮。
  重发会先作废这个用户手上没用掉的旧令牌，所以一个人不会同时握着两条都能验证的链接。
  表单里没有收件地址栏：它只能寄给这个账号已经存着的那个邮箱。
- 邮件发不出去不会让注册失败：账号照建、人照登录，页面上如实说失败原因并指到设置页
  （SMTP 挂了是站点的问题，不该变成"你的密码不对"）。
- **老账号不会被这次升级锁住**：`email_verified` 的默认值是 `1`（SQLite 给已有行回填的就是它），
  所以迁移跑完，注册在这之前的人一律算验证过。批量建号和令牌账号也拿到默认值——
  老师建的班级账号不该因为站长哪天顺手打开开关就交不了作业。
- 站主不会被自己的开关锁死：第一个注册的账号同样要验证才能交题，但他随时进得去
  `/admin/site` 把开关关掉，因为闸门只管交代码与参赛。

动态（`/feed`）是纯文本版的朋友圈：

- 登录即可发，正文最长 4000 字符，一小时最多 20 条（按用户计数，复用登录节流的那张表）
- 只能删自己的；`feed.moderate` 可以删别人的，也可以只隐藏（`visible` 翻转，不删数据）
- 隐藏的条目对公众消失，作者在自己的主页仍能看到标着「已隐藏」的那条，审核者的时间线保留它否则无法撤销
- 时间线按 `id` 倒序游标翻页，`?after=` 取上一页最后一条；只有当页装满才会给出「更早的动态」

## 关注与私信

关注是一张 `(follower, followee)` 的边，个人页上 关注/粉丝 两个数字点进去各自的名单；
互相关注时多一个「互相关注」标记。关注是幂等的（重复点不报错），取消第二次会如实说
"你本来就没有关注"。

私信是一对一的纯文本（不走 Markdown，也不渲染 HTML），会话没有独立的表：一条
`(a,b)` 的对话就是两个方向的消息集合。谁能给你发，由**收信人**在
`/settings → 谁可以给我发私信` 里决定：

| 策略 | 谁能发进来 |
|------|-----------|
| `everyone`（默认） | 所有人 |
| `mutual` | 只接受互相关注的人 —— 即"拒绝陌生私信" |
| `following` | 只接受我关注过的人 |
| `off` | 完全关闭私信 |

几点口径要说清：

- 策略只挡**新发进来**的消息，已经存在的对话仍然看得见；关闭私信不影响你自己往外发
- 被拒的发送会当场说明原因（页面提示"对方的隐私设置不接受这条私信"），不会静默丢弃
- 每人每 2 秒 1 条，与动态、登录共用同一张节流表（窗口 2 秒、窗口内 1 条）；正文最长 300 字。被拒的尝试不算消耗配额，所以"发太快"之后等两秒就能发出去
- 导航栏的未读角标只在 cookie 会话上统计（API/bearer 调用不付这次查询），走
  `WHERE read_at IS NULL` 的部分索引；打开对话就是已读回执
- 还没有做：拉黑单个用户、举报、删除消息、群发与图片

## 每日打卡

首页上「打卡」按钮，一人一天一次，重复点不重复计。打卡后提示**您已连续打卡 x 天**。

漏卡要罚：隔了 n 天没打开，下次打卡时连续天数扣 `3^n`，扣到不足 1 就归 1（当天这一次
总是算数的）。

| 之前连续 | 漏了几天 | 这次打完 |
|---------:|---------:|---------:|
| 30 | 0 | 31 |
| 30 | 1 | 28 |
| 30 | 2 | 22 |
| 30 | 3 | 4 |
| 30 | 4 天及以上 | 1 |

个人主页显示「连续打卡 x 天（累计 y 天）」。日期按**服务器本地时区**算，所以判机换时区
会让"今天"的边界移动；累计天数按打卡记录的行数，不看连续。

## 积分与名字颜色（`/admin/points`）

名字的颜色是**活跃度**的读数，不是一个装饰：蓝 → 绿 → 橙 → 红，四档由积分算出来。
积分是四个维度各自算分再相加，每个维度都是「数一件事发生了几次 × 单位分，再按这一维的上限截断」：

| 维度 | 数的是什么 | 默认单位分 | 默认上限 |
|------|-----------|-----------:|---------:|
| 做题 | 去重后 AC 过的题数 | 10 / 道 | 300 |
| 提交 | 提交次数（含没过的：这是「动手了多少」） | 1 / 次 | 60 |
| 比赛 | 报名过的比赛数（在名单里算） | 20 / 场 | 200 |
| 社区 | 动态 + 帖子 + 评论 | 2 / 条 | 120 |

四者相加得到未衰减的分，再乘一个「闲了多久」的衰减：

```
总分 = raw × (1 − decay_per_day/100) ^ 闲了多少天
```

`decay_per_day=5` 就是闲一天打 95 折，闲 14 天约等于原来的一半；填 0 表示不衰减。
**明细（那一维各值多少分）存的是未衰减的那一份**，个人主页上摊开给你看，所以「为什么我是绿的」
当场能回答。

### 谁去算、多久算一次

后台按管理员设的间隔重算一次（默认 10 分钟，范围 1..1440），所以「积分最多滞后多久」就是那个间隔。
这条腿是**进程内的计时器**（`cmd/fast-oj/main.go` 起、收到信号一起停），间隔每轮重新读，
改完参数不用重启。为什么不挂在请求上：那要从 `submissions`、`posts`、`topics`、`topic_comments`
四张表聚合一遍，等于把排行榜的代价付在每一页。四条 `GROUP BY` 各扫一张表，成本跟用户数无关，
写回时只改真的有变的那些行。

`/admin/points` 上三个按钮共用一个入口：**保存**、**保存并立即重算**、**只按已存的参数重算一次**
（最后那个走库里已经存着的参数，不会把框里没保存的数字偷偷用上）。页面下面是分值从高到低的预览，
调完数字点一次重算就能看见谁因此变绿、谁掉回蓝——这些数字只有在人名上才看得出合不合理。

**总开关关掉**时：分值停在最后一次算出的样子，自动那一档的颜色收回去（人手锁上去的紫与棕照旧不动）。
关掉这套东西的意思是「名字上看不出活跃度」，而不是留下一片没人能解释的红名。

### 六档里只有四档是算出来的

蓝 / 绿 / 橙 / 红由积分和门槛决定，管理员调的是那三个门槛（低于绿就是蓝，档位必须一路往上走，
填反了会自动抬平）。**紫 = 管理员、棕 = 被处罚**两种只能由管理员在账号控制台里指定，
而且设上之后自动重算不会再碰它们——「他是管理员」「他被处罚」是状态，不是活跃度的读数，
让一个数把这两件事冲掉没有道理；想让他重新跟着积分走，选回「跟着积分自动」。

四档不能手选，是因为那等于允许一个人自称活跃而不用活动。

每一处出现名字的地方都跟着这个档位：提交列表、题目下的最近通过、排行榜、动态、帖子与评论、
工单与流水、私信列表与对话、关注与粉丝名单、权限控制台，以及导航栏上你自己的名字。
实现方式是把档位收进读名字的那一条查询（和 `personSQL` 同一条出口），所以**不多一次查询**，
也不存在「这一页忘了改」。库里那一列存的是一个词（`green`、`purple`…）而不是样式文本，
渲染时按词取 CSS 类，于是注入面为零，换配色只改 `style.css`。

它和[每个人自己的配色](#每个人自己的配色settings-的配色那张卡)是两件事：那九个变量是「他觉得什么颜色好看」，
这六档是「站点说他在不在活动」，各走各的，互不覆盖。

实测（本机起的一份演示库）：一个人发 20 条动态、按默认口径就是 40 分；把门槛改成 8 / 24 / 40
再点「保存并立即重算」，页面回报「重算完成，改了 2 个人」，排行榜上他变成 `pt-red`、发 5 条的那个
变成 `pt-green`、没动过的是 `pt-blue`；把其中一人手动锁成紫色之后再点一次「只按已存的参数重算一次」，
页面说「没有任何人的分值或颜色需要改」，紫色还在那里。

### 边界

- 想加第五个维度（比如「被点赞次数」）需要新的表和计数口径，不是页面上填个数字就有的。
- 颜色变化的延迟 = 一个重算间隔；把管理员改的门槛立刻反映到所有人，靠的是那一轮重算，不是保存本身。
- 上限与单位分都归一化过：单位分填 0 会用回默认值（清空框不等于关掉这一档，要关掉有总开关），
  门槛越界或填反了会被抬平，而不是让算法跑飞。

## 用例包约定

zip 里按 `<名字>.in` + `<名字>.out` 成对给出，目录层级会被压平（只取文件名）。

- 名字以 `sample` 开头 → 判为**样例**，展示在题面上且不计分
- 其余为**判题用例**，默认每条 1 分；分值与组名在用例页的「批量改分值与捆绑」表里一次改完整页
- 重复上传按名字替换，**序号保持稳定**，判机顺序不会漂移
- 只有 `.in` 没有 `.out` → 整个包拒收并列出缺哪些
- **组名（捆绑）**：同名即同组，组内任何一条没过（或判机没跑完这一组）整组 0 分；组的分值 = 组内各条之和。分数一律由服务器按逐条判定重算，判机谎报 AC 会被降级
- **判题详情级别**（出题表单里选，只管别人看到的，源码与总分始终归提交者自己）：`none` 只给总判定与得分 → `case` 给逐条判定 → `diff` 再加实测/期望与失败用例（默认）→ `full` 再给判机编号；出题人与持 `submission.view.any` 的人始终看到全部
- 单文件上限 `-max-case`（默认 16 MiB），整包上限 `-max-upload`（默认 64 MiB）

zip 只是批量入口：用例页「批量导入 zip」选一个包即可，同名覆盖、新名排在后面。

**批量改分值与捆绑**：用例页下面那张表，一行一条，改完整页保存。两个不用 JS 的助手——
「平分到判题用例」（除不尽的余数摊给前面几条：100 分 3 条是 34/33/33）与「统一填组名」——
只把表填好，要人核对后点保存才落库。名称与数据文件不在这里改，所以批量操作不可能把一条
用例从自己的文件上改名跑掉；整批一个事务，一格填坏就整批不保存（半张分值表会让下一次提交
按一个不存在的总分判）。

```bash
zip -j cases.zip 1.in 1.out sample1.in sample1.out
```

日常加一两条不用打包：用例页「加一条」里直接填输入输出。

`Content-Type: application/zip` 不能省：`--data-binary` 默认发 `text/plain`，端点按 zip 读体就会一条用例都收不到，而提交只会回报「本题还没有测试数据」。

## 判题方式：普通比较 / SPJ 判题器 / 交互题

一道题「怎么算对」有三档。出题人在**用例页最下面**「判题方式」那一块决定，题面页用一行字把结论告诉学生（那两份程序的源码学生看不到）。

| 档位 | 谁来判 | 判定 | 时限 | 内存 |
|------|--------|------|------|------|
| 普通 | 判机 | 标准输出与答案**宽松比较**：忽略每行行尾空白与整个输出的末尾空行 | 题面时限 | 题面内存 |
| SPJ | 判题器 | 退出码 `0` 对、`1` 错、其他 → **判机故障** | 题面时限 | 题面内存 |
| 交互 | 交互器 | 退出码 `0` 对、`1` 错、`7` 选手程序出错、其他 → **判机故障** | **两侧 CPU 之和**跟题面时限比 | **只算选手那一份** |

判题器与交互器共用同一条命令行约定，作者只需要学一遍：`argv[1] argv[2] argv[3]` = **输入文件、选手输出文件、答案文件**，
程序打印到标准输出的内容成为**评语**。交互题的第二个参数是对话**结束之后**才写进工作目录的转写，
运行时去读只会读到空文件——要跟选手说话就走 stdin/stdout，别开那个文件。

- **时限为什么按两侧之和**：交互器每答一句都要替选手算一次，分开算等于给交互题白送一份时限。
- **内存为什么不算交互器**：它占多少不由学生负责。交互器另有自己的硬顶，顶穿了按**判机故障**收，不能让它把机器顶穿。
- **判题器的预算**：10 秒、512MB、8 个进程，与题面时限无关，也不记在学生的用时里——它自己慢了或崩了是判机故障，不该变成学生的 TLE。
- **交互器的预算**：同一份 512MB 与 8 个进程，但 **CPU 不设单独限值**。它的用时是和选手那份相加后跟题面时限比的，
  各设一份时钟就会出现「按之和判定、按各自杀进程」两个对不上的口径。
- **对话拓扑**：选手 stdout → 交互器 stdin，交互器 stdout → 选手 stdin，判机在中间各搬一份、各留一份转写。
  一侧结束后判机立刻关掉对面的写端，所以规矩的程序会读到 EOF 自己收工，而不是永远等在管道上。

### 存在哪儿、谁能改

源码存在 `judge_programs`（`problem_id` + `kind ∈ {checker, interactor}`），单份上限 256KB。
语言只能是**判机真认识的工具链**（现在与提交页同源：`c` / `cpp`）——允许存一份判机编不出来的语言，
就是让下一个提交的学生吃一条判机故障。**源码留空保存就是撤掉**，题目回到逐字节比较。

改它要 `judge_program.edit`，是一项**单独的权力**，不随 `testcase.manage` 或改题面的委托一起给：
判题器等于把「在判机上执行一段作者写的代码」这件事发出去。没有这项权力的人看到的是只读说明，
而不是整块消失——藏起来会让人以为这道题不支持 SPJ。

### 判机拿到的是同样的牢房

两份程序都由**判机现场编译**，然后在**同一个牢房**里执行（同一套 userns / chroot / rlimit，隔离程度不更高）。
Web 侧不当场试编：编不编得过由判机那台机器的工具链说了算，替它说「这份能编」才是假保证。

- **两份都配了 → 判机直接拒判**（判成判机故障，写明两者只能留一个）。它不会悄悄挑一个来用；保存时用例页就会提醒。
- **编译失败、判题器崩溃、超时顶穿它自己的预算 → 判机故障**，detail 写明是哪份程序的问题。学生的代码不背这个锅，但那条提交确实废了。
- 评语显示在详情页「判机信息」那一栏，受本题**详情级别**约束（低于 `diff` 学生看不到）；
  多条用例同时失败时只留**第一条**的评语，所以判题器那句「为什么判错」要写成任何一条用例都能自洽的话。
- 判题器判定过的题目不再有「第 N 行你输出 X、答案是 Y」那种逐行对照——答案不唯一，那种对照本身就没有意义。

### 部署：服务器与判机要一起升级

判题器与交互器的源码是**跟着工单发给判机**、由判机编译的。旧判机不认识这两个字段，会按
逐字节比较判掉带 SPJ 的题——而页面上写着「本题由 SPJ 判定」，那就是当着学生的面讲假话。
自从判机开始自报能力（`capabilities`），这种事在派单这一层就被挡住了：**没自报 `checker`
的机器领不到 SPJ 题的工单**，那条提交会在队列里等一台判得了的机器，而不是被将就判掉。
所以升 SPJ / 交互题 / 版本选项时：先把判机升上去，那道门才会打开；不然提交只是排队，
`/judges` 上能看到哪台机器没自报能力。同理适用于提交页的版本选项（`-std=` / `-O2`）。

## Python 提交：护栏装在解释器里，边界还是牢房

判机收 `c` / `cpp` / `python`。Python 那一支不编译：判机把源码写成 `main.py`，在同一目录里
再落一份 `internal/judge/pyguard.py`，然后用

```
python3 -I -B -S -X utf8 <工作目录>/pyguard.py <工作目录>/main.py
```

跑起来——`-I` 让 `PYTHONPATH` 之类的环境变量进不来，`-S` 不跑 `site`（少一条把 site-packages
塞进 `sys.path` 的路，`pip` 更进不来），`-B` 不落 `.pyc`，`-X utf8` 让学生打印中文时不跟着
`LANG=C` 变乱码。

- **时限原样算**：解释器启动那几十毫秒 CPU 也算在学生的用时里，不放宽。
- **内存只算学生那一份**，但题面内存低于 **32MB** 时站点直接拒收 Python：实测 CPython 3.14
  空跑常驻就要 ~9MB，再 import 一点标准库只多不少——那种题面判的不是学生的程序，是解释器。
  提交页会把这句话当面说明，而不是让提交进去撞一条 MLE。

### 护栏挡什么

`pyguard.py` 装的是一个 CPython **审计钩子**（`sys.addaudithook`，装上就摘不掉，学生代码里
`exec`/`eval` 出来的东西同样经过它）。挡下的是"离开这次运行"的那几扇门：`subprocess`、
`socket`/`ssl`/`select`/`selectors`/`asyncio`、`ctypes`、`multiprocessing`、`pty`、`webbrowser`、
`http`/`urllib`/`ftplib`/`smtplib` 等网络库，以及 `pip`/`ensurepip`/`venv`/`setuptools`/`distutils`。
撞到钩子时学生看到的是一条 `RuntimeError: 判机不允许……`，判定是 **RE**，原因在 stderr 里。

名单**只列真能出门的那几扇**，这有实测依据：`pathlib` 在 3.14 会去 `import fcntl`，早先那份
名单把 `fcntl` 也禁了，于是 `import pathlib` 直接炸——而且只在 Linux 上炸（Windows 没有这个模块）。
同理 `os`、`shutil`、`signal`、`threading` 都留着：禁 `os` 会让 `random`/`pathlib`/`tempfile`
一起塌。有一条测试同时盯这两半（该挡的真挡住、常用的还能用）。

**护栏是纵深，不是边界**。它假定牢房开着——"不许离开这次运行的目录"这条线是 chroot 画的。
所以判机有两道闸门：

1. **启动自测**（`judge.PythonProbe`）：一次正常程序必须跑通，一次想起子进程的必须被挡下来，
   而且当前配置必须真能建牢房。任何一条不过，就把 `python` 从这台判机的名单上摘掉，并把原因
   挂在 `/judges` 的备注里——站点因此不会摆出一个"能选但判不了"的选项。
2. **领单时**（`internal/judgeagent`）：`!judge.Jailed()` 而工单里有任何一份要跑的 Python
   （提交、Python 写的判题器或交互器都算）→ 判机故障 + 那句原因。

`/judges` 上能看到这台机器实际的口径：`沙盒已启用（…）；Python 自测：…` 或者被摘掉的原因。

### 判题器与交互器也能用 Python 写

`BuildAux` 对不编译的工具会把那份护栏一起落进目录，交回"解释器 + 护栏 + 源码"这条命令行，
所以 SPJ 与交互器的 `argv` 约定和 C++ 完全一致（`argv[1..3]` = 输入 / 选手输出 / 答案，
退出码 `0/1/7`）。作者那份 Python 与学生那份拿到的是同一层护栏、同一个牢房、同一份
`10 秒 / 512MB / 8 进程` 的预算。

### 部署

判机那台机器要有 `python3`（`Dockerfile.judge` 里 `apt install python3`）。**服务器与判机要一起升**：
旧判机不认识工单里的 `python`，会按"这台机器没有这门语言"回一条判机故障——那条提交废了，
但比悄悄用另一套口径判掉要好。启动日志与 `/judges` 会写明它到底有没有这门语言。

## 比赛（限时 + 独立榜 + 加入码 + 队伍，OI/IOI/ACM 三种赛制）

比赛只负责「谁在什么时间对哪些题交了什么」。**每题得分仍然由 M13 那套逐用例计分给出**（组内全过才给分），
比赛一层不另起算分逻辑，所以一场比赛的榜和平时练习的得分不会互相打脸。

### 状态与时间

状态**不落库**，永远按当前时间算：`未开始 / 进行中 / 已结束`。没有定时任务，也就没有「到点没改状态」这种事故。
落库的开关只有两个：`榜单公示`（封榜与否）与`出现在列表`（比赛本身是否公开）。

时间是**本站服务器时区**：表单里填 `2026-10-14T20:00` 就按服务器本地时间解释，页面也按同一时区显示。
全站不提供用户时区，所以「主办方填的时间」和「选手看到的时间」是同一个数。

### 计分公式

设某题在题目里的满分为 `T`（判题用例分值之和），比赛里给该题设定的分为 `P`（填 0 表示沿用 `T`）：

```
比赛内该题满分 max = P（P>0 时）或 T
某次提交挣到的分   award = round(raw × P / T)   （P>0 且 T>0）
                      raw                        （否则，raw 就是逐用例得分之和）
```

> 所以「比赛设定分」是**等比缩放**，不是凭空加分：只过了半数分值的人，在比赛榜上也只拿到一半。

三种赛制，别混：

**OI 赛制**（CSP-J/S、NOIP、NOI 用的就是这个，也是默认值）

- **同一题取最后一次提交**——不是最高分。做出来又改坏了，就算改坏的那次
- 总分从高到低；**同分就是同名次**，不比用时，也不比提交次数
- **比赛进行期间不出榜**：除主办方外任何人（包括自己）都看不到榜单，页面说明原因
- 榜上**没有用时列，格子里也不显示尝试次数**：只有每题得分与总分
- 配套用法：比赛期间把题目的「判题详情级别」设成 `none`，才是完整的闭卷

**IOI 赛制**

- 每题取**最高分**那次提交
- 总分降序；**同分再比总用时**（用时 = 各题那次最高分的 `判定时刻 − 开始时刻` 之和，没拿分的题按最后一次尝试计时）
- 格子里给灰字用时，尝试多于一次时一并标出

**ACM 赛制**

- 一题只认**首次 AC**：该题计 1 解题、满分 `max`
- 罚时 `= Σ(首次 AC 时刻 − 开始) + (该题首次 AC 之前的非 AC 判定次数) × penalty_ms`
- `CE` 不罚；`IE`（判机故障）**既不算尝试也不罚**；WA/TLE/MLE/RE 算
- 没 AC 的题只显示尝试次数，不给时间
- 名次键：`解题数 降 → 罚时 升`

**三种共同**：只有 `status=done` 的提交入榜（判机中、排队中、判机超时的都不在榜上）；
名次并列就同名次，下一个名次照常跳过（1 2 2 4）；比赛榜**不影响**全站 `/rank`。

### 队伍

`每队人数 > 1` 时启用队伍赛：

- 加入比赛时没指定队伍，就自动进一支以你自己 handle 命名的队，保证没人掉在榜外
- `op=create / join / leave`：建队并进队、按队名加入、退队
- 榜上一个队伍是**一个竞争者**：每题取队内最优，尝试次数按队求和（所以罚时也是队级）
- 把每队人数**改小不会拆开已有的超编队伍**，只是不再允许新的人加入

### 加入码与封榜

- 加入码留空 = 公开赛，任何人免码加入；填了码 = 私有赛，加入时必须对上码（服务端常数时间比较）
- 加入码**只出现在主办方的编辑表单里**：比赛列表根本不查这一列，主页、榜单、URL、日志里都没有
- 比赛结束后不再收人（防止赛后补进榜单改写比赛结果）；未开始可以先报名
- **封榜**：`榜单公示` 关着时，别人看不到彼此——成员只看到**自己那一行**（名次仍是全场真名次），
  非成员只看到一句说明；主办方看得到完整榜单，并标注「封榜中」
- **结束不会自动放榜**，要在编辑页手动勾「榜单公示」。这是刻意的：忘了关设置就是泄题，多一次点击不会

### 权限

| 操作 | 需要的权限 |
|------|-----------|
| 建比赛 | `contest.create` |
| 改/删自己的比赛、挂题、看加入码 | 该比赛 owner |
| 改/删他人的比赛 | `contest.manage.any` |
| 出题、用题目 | `problem.create` 等原有权限，比赛不额外放行 |

比赛进行中**不会**因为「在比赛里」就多看到别人的源码或逐用例明细：判题详情级别照题目自己的设置走。
比赛内的题目列表只对成员与主办方开放；未公开的题目要挂进比赛，挂的人必须能编辑那道题，
否则公开一场比赛就等于替别人公开了题目。

## 帖子（求助贴 / 社区贴 + 评论）

两类帖子，一张表：

| 类型 | 挂题目？ | 从哪进 | 谁在管 |
|------|---------|--------|--------|
| **求助贴** | 必须挂一道题 | 题目页的「求助贴」→ `/problems/{pid}/topics` | 按题目聚合，别人搜题就能看到 |
| **社区贴** | 不允许挂题 | 导航栏「帖子」→ `/topics` | 一个页面统一管理 |

- 「必须 / 不允许」写在表的 `CHECK` 里，不是靠每个调用方记得查——所以不会出现半条挂空的求助贴
- **删除题目会连带删掉它的求助贴与评论**（外键级联），删号同理
- 正文与评论都走题面同一套 Markdown + `$KaTeX$` 渲染管线，转义策略全站只有一份
- **必须登录才能发帖与评论，未登录只能浏览**：写操作一律先回登录页并带上原地址
- 节流：发帖每人每小时 10 帖、评论每人每小时 60 条，与动态分开算，灌水贴刷不掉别人的讨论
- 删除权限：自己写的随时删；删别人的要 `topic.moderate`
- 首页展出**最近 10 条**帖子（两类混合），一行两个方块卡片，窄屏自动退成一列

## 工单（用户提单，管理员处理）

与帖子的根本区别是**私密**：`/topics` 谁都能读，`/tickets` 只有作者与持 `ticket.handle` 的人读得到。
申诉里会写"我认为标准答案错了"，举报里会写别人的用户名，这些都不该出现在公开页上。
所以陌生路径返回 **404 而不是 403**——工单的存在本身就是信息。

| 类型 | 用来做什么 |
|------|-----------|
| 申诉 | 判题觉得判错了、数据弱、想请人复核某次提交 |
| 故障建议 | 站点毛病、题目毛病、功能建议 |
| 举报 | 举报某个用户或某次提交 |
| 账号 | 邮箱、封禁、注册之类账号上的事 |
| 其他 | 以上都不是 |

- 可以挂一道题或一次提交（**只能挂自己的提交**，别人的提交号一律报"找不到"）
- 状态 `待处理 → 处理中 → 已解决 / 已关闭`。处理人改状态时顺手记名为经办人；退回待处理会清空经办
- 作者没有 `ticket.handle` 也能**关自己那张**（"我自己解决了"是会发生的事），其余状态改不动
- 改状态写成流水里的一行，和人的回复同一条流：一页看完整个经过
- 导航栏「工单」对登录用户出现，**未处理数只给处理人算**（普通用户看不到队列有多大）
- 速率：每人每小时 5 张工单、30 条回复
- 通知：没有邮件也没有推送，处理人靠导航栏那个角标。要做提醒算下一期

## 身份与权限

| 凭证 | 怎么来 | 能干什么 |
|------|--------|----------|
| `-admin-token` | 启动参数 | 运维引导凭据：驱动判机队列、以及在 `/admin/claim` 给第一个账号设密码。不是日常登录方式 |
| `-judge-token` | 启动参数 | 领取任务、取用例正文、回报结果 |
| 邮箱 + 密码 | `/register` 自助注册 | 登录成普通用户（session cookie） |

登录与会话：

- 注册要邮箱 + 用户名 + 密码（≥10 位，bcrypt cost 默认 11）；**邮箱暂不发送验证邮件**，注册即可用
- 登录可用邮箱或用户名；失败提示统一为「账号或密码不正确」，不区分哪一步错，避免枚举账号
- 同一来源 IP 在 15 分钟内失败 10 次返回 429；计数在库里，重启不会把锁定清零
- session cookie `fastoj_session`：`HttpOnly` + `SameSite=Lax` + `Path=/`，30 天；上 TLS 时加 `-secure-cookies`
- 每次登录新建 session；改密码吊销该用户全部 session
- **CSRF**：非 GET 请求统一过闸门，只有「凭 cookie 认证」的请求被要求带 `csrf` 字段或 `X-CSRF-Token` 头，与 session 里的 token 常量时间比较；`Authorization: Bearer` 的 API 调用不带 cookie、天然免疫，不做要求
- `/login?next=` 只认站内路径，`//evil`、`/\evil`、绝对 URL 一律回落到 `/`
- 引导令牌与判机令牌都做常量时间比较；除此之外系统里没有第二种凭据
- 隐藏题对无权限者一律 404 而不是 403，避免被枚举
- 提交的判定结果公开；源码、逐用例明细、判机差异信息只有本人或管理员可见
- 关闭注册：`-no-register` 与后台 `/admin/site` 的「允许自助注册」取与，任一方关掉后 `/register` 即 403
- 个人简介（`/settings`）与动态正文走题面同一条 Markdown 安全管线，见[首页、站点设置与动态](#首页站点设置与动态)

### 细粒度权限

不是"普通用户 / 管理员"两档了事：每个能力是一项可以单独授予的权限，网页控制台 `/admin/perms` 逐项开关。

| 权限键 | 含义 |
|--------|------|
| `problem.create` | 创建题目 |
| `problem.edit.any` | 编辑他人创建的题目 |
| `problem.publish` | 公开 / 隐藏题目（作者本人也不能隐藏自己的题，需要这一项） |
| `testcase.manage` | 管理他人题目的用例 |
| `judge_program.edit` | 写题目的判题器与交互器：**把一段作者写的代码送上判机执行**，所以不随 `testcase.manage` 或改题面一起给 |
| `contest.create` | 创建比赛 |
| `contest.manage.any` | 管理他人创建的比赛 |
| `user.manage` | 改角色、封禁 / 解封 |
| `permission.manage` | 授予与回收上面这些权限 |
| `judge.view` | 查看判机框与队列 |
| `feed.moderate` | 删除他人动态 |
| `topic.moderate` | 删除他人帖子与评论 |
| `ticket.handle` | 处理工单：看全部、回复、改状态、删单 |
| `site.settings` | 修改站点设置与首页 |
| `submission.view.any` | 查看他人源码与逐用例明细（作弊调查用） |
| `stats.view` | 查看站点统计（人数、提交、请求量） |
| `ip.manage` | 封禁 IP 与查看按地址流量：能封人的权限不该顺手给只看数据的人 |

上面这些都是**管理侧**权限：给了就等于工作人员。另有三项是**普通人本来就有的日常能力**，
管理员在权限控制台里对某一个人点"收回"即可禁用——用于刷屏、灌水、拿 AI 在比赛里乱试这类
情况，处置的是"这一扇门"，不是整个账号（历史成绩、私信、题目页都还得用）：

| 权限键 | 默认 | 收回之后 |
|--------|------|----------|
| `feed.post` | 人人可用 | 不能发动态；看别人的动态照旧 |
| `topic.post` | 人人可用 | 不能发帖与求助；读帖、看题目讨论区照旧 |
| `contest.join` | 人人可用 | 不能加入比赛，**也不能在已加入的比赛里提交**（只挡加入的话，名单里的人还能继续交）；练习提交不受影响 |

规则：

- 题目记录 `owner_id`。**创建者天然能改自己的题**，不必持有 `problem.edit.any`；`testcase.manage` 是给"只维护测试数据"的人的独立通道
- 生效权限 = 角色默认 ⊕ 个人覆盖（个人覆盖双向生效，可以只从管理员手里收回某一项）
- **控制台拒绝修改你自己**：改自己的权限/角色/状态一律 400，避免把自己锁在门外
- 封禁（`status='banned'`）立即吊销该账号全部会话；解封不需要重设密码
- 改角色后能力集在下一个请求就重算，不需要对方重新登录
- 拒绝时回答里会点名缺哪一项（例如 `缺少权限：problem.publish`），方便对接脚本
- 被禁用日常能力的人，页面上给的是"你被禁止发动态。想恢复请提交一张工单说明情况。"这种
  一句话原因，而不是一个只会 403 的输入框；匿名读者仍然看到"登录后就能发"

### 用户标签：名字后面那句话

账号控制台上每个人都能贴标签，形如 `admin [站长] [退役选手]`。规则是：最多 **3 个**，
每个最长 **12 个字**（按字算，中文一个算一个），用逗号分开——中英文逗号都认，多余的空白会自动去掉。
逗号与方括号不能出现在标签里，因为那两个是分隔符：放行就等于一个人能给自己名字里造出第二个标签，
或者把别人那一行搅乱。

标签**不是权限**：贴上「管理员」不会让这个账号多出任何能力，摘掉也不会有。所以它不进
那道改权限要的身份再确认（[见下](#改权限之前的身份再确认2-分钟)）——那道门是给"一改就改变一个人能做的事"
准备的，标签贴错随时能改回来，把每贴一个标签都变成一次密码输入只会让管理员绕着走。
写它要 `user.manage`。

凡是用这个名字的地方都跟着显示：提交列表、排行榜、动态、帖子与评论、工单、私信、关注与粉丝名单。
做法是把标签折进读名字的那一条表达式里（`personSQL`，见 `internal/store/user.go`），
所以不多一次查询，也不会出现"这一页忘了带标签"。注销账号时标签和身份一起抹掉——
留下的那一行署名是「封禁用户」，不该还挂着生前的话。

审计里记的是**归一化之后**的那一串（`新生,退役选手`），不是表单原文，所以事后查到的就是
页面上真正显示的那个形状。不合格的输入直接报错并说明哪一条不合格，不会"保存成功但其实被丢了"。

已知边界：库里那一列如果被人在 SQL 里手改成带分隔符的样子，SQL 拼名字那一路会把原文拼进去
（`html/template` 的转义保证它进不了标签、属性或脚本，最坏是名字后面多出一串怪字符）；
需要逐个标签用时走 `ParseTags`，它会把不合格的丢掉。

### 改权限之前的身份再确认（2 分钟）

权限控制台的四项写动作——逐项授予/收回、改角色、改状态、注销账号——除了各自的权限键，还要求
**当前这个会话最近把密码再输过一遍**。没输过就不放行：那一页只读（按钮根本不渲染出来），点到的
动作会被送回一句"请输入你的密码"。确认一次管 **2 分钟**，这期间这一路的改动不再问；2 分钟一到
重新问。

- **它补的是 CSRF 补不到的那一段**：CSRF 挡的是"别人替你点按钮"，挡不住拿到你 session cookie 的人。
  而这一扇门后面放着的是"谁能做什么"。所以要多一道只有本人密码能过的确认
- **判断记在会话上（`sessions.step_up_at`），不是账号上**：手机上的确认不会替网页上的会话背书；
  反过来，被偷的那个会话自己背着失败次数。这也意味着放行那一侧**不多一次查询**——这一列跟着
  `authenticate` 本来就要读的那一行会话一起出来，代价是一次整数比较。默认 0：登录成功不等于
  "刚刚证明过密码"
- **连错 5 次当场踢掉这个会话**，并且只踢这一个（本人另一台设备上的登录不受影响）。计数键是会话
  id 的哈希前缀——会话 id 本身就是凭据，而 `login_attempts` 那张表会被别的管理员看到，不能把凭据
  抄进去。这条拒绝会进审计（`step_up.denied`），它是"篡改未遂"最直白的一条记录
- **管理令牌那一路不受这道门管**：它每一次请求都自带那个秘密，不存在"cookie 被人拿走"这回事
- 拒绝的提示里只有"还剩几次机会"，**密码不回显、不进日志、不进审计**
- 顺序上先过权限、先过"不许改自己 / 站主免疫"，再轮到这道确认：那两条拒绝更具体，不该被一句
  "请先输密码"盖过去
- **说清挡不住什么**：知道这个管理员密码的人挡不住——那种情况与"他把账号给了你"没有区别，任何
  会话保护都给不出更强的保证。这一道门把"偷到 cookie"和"拿到账号"分成两件事，前者从此需要后者

### 超级管理员（站主）

第一个坐上管理员位子的人是**站主**，他的权限、角色和状态**别的管理员动不了**——这是
一条数据层的规则，不是页面上的礼貌：

- 位子存在 `site_owner` 这张只允许一行的表里。`users.role` 带着 `CHECK (role IN ('user','admin'))`，
  加第三个值要重建被十几张表外键引用的 `users`，代价远大于收益
- **先到先得**：站点还没人认领时，第一个注册的人坐上去，同时进入 admin 层（别的路径都读
  `users.role` 判管理员）。已经有人在用的站点不认路人注册——只有拿 `-admin-token` 在
  `/admin/claim` 接管的那次能补这个位子，所以"老师先批量建完全班的号、自己最后才注册"
  这种顺序不会把最高权限交给最先点注册的学生
- 老库升级时，迁移 0017 把位子交给**最早的那个管理员账号**，不会因为升级凭空换个主人
- 免疫落在数据层：`SetUserPermission` / `ClearUserPermission` / `SetUserRole` / `SetUserStatus`
  对站主一律返回 `ErrSiteOwner`；`EffectivePermissions` 里"站主"那一路压过角色默认与个人覆盖，
  所以手工往 `user_permissions` 插一条收回也不生效
- 权限控制台读得到站主那一行（标着**超级管理员**），但一个按钮都没有
- 位子不可转让。真要换主人，直接改 `site_owner` 那一行（停服 → `sqlite3` → 起服）
- 部署后第一件事应该是**自己先把站点认领下来**（注册或 `/admin/claim`），别把空位子留给路人

建题、传用例、看判题数据现在都可以只给到"能出题但不能隐藏题"这种粒度；`-admin-token` 对应的 admin 账号默认持有全部项。

## 注销账号（不是封禁，也不是删除）

权限控制台每个账号下面有一个注销表单（需要 `user.manage`），要把用户名原样敲一遍才放行。
它抹掉的是**身份**，留下的是**行为**：

| | 注销之后 |
|---|---|
| 用户名 | 释放，下一个人可以原样注册；本人改成 `banned-<id>` |
| 邮箱 / 密码 / 昵称 / 简介 | 全部清空（密码是哈希，本来也还原不出来） |
| 会话与个人权限覆盖 | 全部删掉，正在登录的浏览器立刻掉线 |
| 提交、判题结果、逐用例明细 | **一条不删**，作者署名显示为**封禁用户** |
| 动态、帖子、评论、私信、打卡 | **一条不删**，同上署名 |
| 排行榜 / `?user=` 筛选 / 统计 | 仍然算得进去，只是名字是封禁用户 |

为什么这么设计：

- **不能删行**。`submissions`、`posts`、`topics`、`runs` 都靠 `user_id` 找作者，删行会顺着
  外键把判题记录一起带走，而这里要的是"记录还在，只是标注成封禁用户"。
- **用户名必须改名而不是留着**。历史记录靠 `user_id` 关联，把 `handle` 原地留给下一个人
  就等于把上一任的提交、帖子算到新人头上。`handle` 上有 `UNIQUE COLLATE NOCASE`，而注册页
  的 `validHandle` 只收 ASCII，所以 `banned-<id>` 既腾出了原名，又是一个仍然打得开的个人主页
  地址（墓碑页保留历史，但去掉关注与私信入口——那两样后面已经没有人了）。
- **下一任接不到上一任的任何东西**：新注册的是另一个 `user_id`，所以 `/u/<原名>`、
  `/submissions?user=<原名>`、主页与统计都只看得到新人自己的东西。
- **署名统一由 `store.personSQL` 决定**：已注销的账号在任何地方都显示封禁用户，绝不打印
  那个已经属于别人的 handle。顺带兑现了注册页早就写着的一句话——昵称要显示在题目记录与
  排行榜上（这些视图以前只印 handle）。

拦阻条件（都会说清原因，不会静失败）：

- **站主注销不了**：他是唯一能动他的人；**自己也注销不了**，沿用控制台"不许动自己"。
- **名下还有题或比赛时先拦住**并报出数量：注销会让这些题永远没有作者、比赛没有主办方，
  先把题转走或删掉、比赛删掉，再来注销。
- **不可逆**：注销之后所有改动账号的入口都拒绝这行（包括"解封"）——那个用户名可能已经被
  别人拿走了，恢复身份就等于冒名。真要留证据请先在别处记下原用户名。
- 封禁（`status='banned'`）与注销是两件事：封禁是可逆的、名字还是他的；注销不可逆、名字自由。

## 运营页：统计、批量建号与注册限流

`/admin/stats`（需要 `stats.view`）一页回答"这个站现在怎么样"：注册用户与启用/封禁/管理员
拆分、提交总数与**人均提交**、通过率、题目与用例数、动态/帖子/评论数、比赛与工单、判题队列
与在线判机数、判定分布、最近两周的提交、提交最多的题，以及 **GET、POST、其他请求**各来了多少
次和平均每秒多少。

- 请求计数活在内存里（`atomic`），**没有**在每个请求上加一次写库：这个项目的热路径就是判题与
  页面渲染，不值这个钱。代价是那几行写的是"本次运行以来"，进程重启归零——页面上就这么标注
- 人均提交的分母是"提交过的人"，不是全部注册用户：后者会把从没打开过站的账号算进平均分。
  通过率同理只算判完的，排队中的提交不该看起来像一片失败
- 所有数字当场从库里查，没有第二份需要维护的计数器

`/admin/accounts/new`（需要 `user.manage`）是批量建号：一个班四十个学生不该用注册表单填四十遍。
两种填法——贴一份名单（一行一个 `用户名` 或 `用户名,邮箱`，配一个统一初始密码），或者
`前缀 + 起始号 + 个数` 一次生成一批、每个号一个随机密码。结果页把用户名与初始密码列成表，
还有一份能直接复制去打印的清单；**密码只在这一个页面出现一次**，库里存的是哈希，刷新就看不到。

- 建出来全是 `user` 层的普通账号：批量入口不是拿权限的后门
- 用户名、邮箱、密码走注册页同一套规则；坏行说清是第几行、坏在哪里，并且**一个都不建**
- 撞名只跳过那一行（一次事务里 `ON CONFLICT DO NOTHING` + 看影响行数），一个班里有两行写重了，
  其余的照样建好，不会出现"建到一半"的名单
- 邮箱留空必须写成 `NULL` 而不是空串：那两条唯一索引是 partial（`WHERE ... IS NOT NULL`），
  空串会被算进去，第二个不填邮箱的号就会莫名其妙"撞名"

注册限流：**一台机器每分钟最多 `-register-per-minute` 个账号（默认 1）**，按两把键一起算——
`register:ip:<地址>` 与 `register:dev:<浏览器设备号>`，任何一把超了就拒；每小时 20 个的总量上限
照旧保留（`register:hour:<地址>`，一条独立的键，因为 `login_attempts` 里一个键只有一行）。
被挡住时表单保留已经填过的内容，只多一句原因。

- **网卡的 MAC 地址拿不到，这是事实不是取舍**：MAC 只存在于同一个二层网络里，请求一过路由器
  就被换成路由器自己的地址，HTTP 里从头到尾没有它。所以"这台机器"用注册页生成的随机号
  （存 `localStorage`，随表单一起提交）来近似
- 设备号**只校验格式、不信任内容**：它可以被伪造、被清空，所以只能当限流键，不能当身份，
  也不能当授权依据；格式不对就当没有，不给它建桶
- 清掉站点数据能换一个新号，这正是 IP 那条键留着的原因；真要收紧就调 `-no-register` 或后台开关
- 浏览器没有 `localStorage`（隐私模式）时脚本静默跳过，注册照旧，只是少了设备号那一把键

### 人机验证窗：观感是演给人看的，等待是强制的

同一个地址动作多了之后（**注册从第二个号起**、**登录从第 3 次密码错误起**），表单上会压出一个
窗：先转圈显示"正在验证你是人类…"，时间走完才出现那个"我是人类，不是机器"的格子，点它才放开
注册/登录按钮。**页面上不写还剩几秒**——那串数字只替脚本报时。等待秒数按频繁度往上加：第一次
触发是 `1..5` 秒，之后每多一次动作上限 `+1` 秒，最多加到 `-human-verify-max-seconds`（默认 20）。

- **两道强制，都写在服务端**：`verify_challenges` 表里的 `ready_at`（等待时间）与 `verified`
  （那一下真的点到了）。点格子是一次独立的 `POST /verify`，服务端只在**等待已走完、令牌确实是
  这个地址领的、用途对得上、而且请求长得像浏览器**时盖章；注册/登录只核销盖过章的令牌，核销是
  一次性 `DELETE`。所以"抓页面 → sleep 够秒数 → curl 交表单"这条实测存在的绕法已经不成立
- **形状检查抬门槛，不做识别**：`Sec-Fetch-Site: same-origin` 直接算数；老浏览器不带这套头，
  就要求 UA 是 Mozilla 系 + 声明收 HTML + 带 `Accept-Language`（`curl -A Mozilla/5.0` 缺第三条）。
  UA 自报 curl/wget/python-requests/Go-http-client/okhttp/java 之类的直接不算。**一个肯照着我们这页
  JS 抄一遍、把四个头都补上的脚本，这一关拦不住**——谁都别把它当墙，它只是把"随手写个脚本"和
  "决心要打这个站"区分开
- **真正掐住批量注册的还是计数与邮箱**：`-register-per-minute`（默认 1）加每小时 20 个的按地址
  总量，加上 `/admin/site` 的「注册需要验证邮箱」——没验证的号能读能登录但交不了题。要挡刷号，
  开那一个开关比调这里的秒数有用得多
- **注册第一次不弹**：这个地址本小时还没有成功注册的记录就直接放行；被限流、被表单校验挡回去的
  那些都不计数，只有真建了号才算一次。登录反过来：打错一两次密码是学生日常，攒到 3 次才弹；而
  "没点格子"或"没等够"的那次提交**不算密码错误**，不会把人推向 10 次那条真锁
- **一个地址一个用途只留一个正在计时的窗口**：被打回重填、开两个标签页、有人拿废令牌试一次，
  都接着用原来那个倒计时，绝不另发一个从此刻重新计时的——否则手快点的代价就是重新等满一遍
- **没有 JavaScript 也能走通**：格子的真身是 `<form action="/verify">` 里的一个提交按钮，点它
  就是那次请求；服务端盖完章把人送回表单页，那里显示"验证好了"，再点一次提交即可。代价是重填一次
  表单。找不到提交按钮之类的结构变化时脚本什么都不拦——宁可没有这个窗，也不能让正常人交不了表单
- 全班共用一个出口 IP 的那天，等待会从第二个号开始挨个落到每个人头上（一号几秒，越往后越久）。
  嫌吵就调小 `-human-verify-max-seconds`，写 `0` 整套关掉，退回原来那两条限流

## IP 封禁与按地址流量

`/admin/ips`（需要 `ip.manage`）做两件事：看每个来源地址打了多少，以及把某个地址整站拦死。

| 项 | 说明 |
|----|------|
| 写法 | 单地址 `203.0.113.9`，或 CIDR 网段 `203.0.113.0/24`。不接受域名（按名字封要在请求路径上做解析） |
| 范围 | **整站拦死**：题目页、静态资源、登录与注册、`/healthz`、判机回调一律 403 |
| 谁封的、为什么 | 列表显示封禁人、原因和这个地址被拒了多少次 |
| 流量表 | 每个地址的 GET / POST / 其他 / 注册数 / 被拒数，Top20；从这一行可以直接点"封这个地址" |
| 网段的数字 | 一条 `/24` 旁边显示的是段内所有被记录地址的和，否则网段看着像没在起作用 |
| 环回地址 | 拒绝封禁：`127.0.0.1` / `::1` 一封就是封全站，连管理入口一起锁死 |
| 全世界（`0.0.0.0/0`、`::/0`） | 同样拒绝：这条封的是"所有地址"，包括按下按钮的人；封完这一页自己也打不开，谁都没法再解封。要停站用站点开关 |
| 内网地址 | 允许封。学校机房的 `10.x` / `192.168.x` 是有意义的粒度 |

三道自己保护自己的设计：

- **先看流量再封人。** 页面把 Top 榜和"被拒次数"摆在封禁表单下面，因为最容易犯的错不是
  没封住，而是把学校出口或判题机所在的地址封了——那一下整站就停了。判机回调同样会被拦，
  这个后果写在页面顶部。
- **来源全是 127.0.0.1 时自动收起。** 服务器上跑着同机反向代理（或只有本机能访问）时，
  服务器看到的每个访客都是同一个环回地址：这时候按 IP 封既封不掉任何人，又随时可能变成
  自杀。所以 24 小时内没出现过非环回来源，这一页就自己收起、导航入口消失，并在直接打开时
  说明为什么。**封禁的执行不受这个闸门影响**——封环回与封 `0.0.0.0/0` 都在创建时被拒绝，
  不存在误锁。线画在 `/0` 这一条：`128.0.0.0/1` 这种半球网段仍然允许，封不封得对是操作者的
  判断，但"把所有人一次性关在外面并且没人能再进来改"不是判断，是事故。
- **只信 `RemoteAddr`，不信 `X-Forwarded-For`。** 转发头是任何客户端都能编的：信了就等于
  让被封的人自报一个干净地址，还会把统计表灌满假地址。真要上反代，就把代理透传真实来源的
  方式配好（并在服务端只接受来自内网的转发），而不是顺手信任头部。

流量计数活在内存里，意思是"本次运行以来"，进程重启归零——为了几个数字在每个请求上加一次
写库不值，这跟统计页的 GET/POST 总量是同一个取舍。**封禁本身在库里**，那是管理员的决定，
必须活得比进程久。来源地址数超过 5000 之后不再记录新地址，页面会说明：没这个上限的话，
换一个来源地址刷就能把这张表撑到进程死掉，统计功能自己会变成攻击面。

## 安全审计流水

`/admin/audit`（需要 `ip.manage`）是特权操作的账本：每一行是"什么时候、谁、对什么做了什么，
从哪个地址"。形状跟工单流水（`ticket_replies.event`）一样——**只追加**：代码里没有改它或删除它
的函数，页面上也只有看。0027 建表，`at` 与 `action` 各一条索引。

| 项 | 说明 |
|----|------|
| 记什么 | 授予 / 撤销 / 清除单项能力、改角色、封号与解禁、注销账号、封与解 IP、保存站点设置、保存与撤掉判题器、删除用例、清空用例、删题、删比赛、把题目移下比赛、工单改状态、删工单 |
| 判机那一侧 | `judge.denied`：拿着不对的凭据打 `/judge/*` 被拒时记路径、原因与来源地址。判机令牌能领工单也能写判定结果，"有人在敲门"这件事原先只有一行通用请求日志（方法/路径/状态码），既没人也没原因 |
| 操作者 | 存的是**当时那个名字**的文本，另存 `actor_id` 只做跳转。账号注销后用户名会释放给下一个人注册，只留 id 的那条要么变成「封禁用户」，要么更糟——变成几个月后同名的人的罪名 |
| 长度 | `actor`/`action`/`target`/`detail`/`ip` 各 64/64/200/500/64 字（按字数算，汉字不会被切成半个），超出截断并留 `…`。一张只追加的表如果一行能塞几 MB，"能操作一次"就变成"能把站点写满" |
| 写不上账 | 只打一条 stderr 错误，**不挡动作**：能写满磁盘或拖住 SQLite 的人不该因此拿到整站的开关。审计表必须是被动的那一方 |
| 泄露 | 令牌值、密码、会话 id 一律不入库；`actor` 只写凭据的形态（`bearer 令牌` / `会话 Cookie` / `无凭据`） |

原来那行 slog 全部保留：盯着 stderr 看一次改动落地，比事后翻页面快。审计补的是"进程已经不在了"
之后还得能问出来的那一部分。

## 判机协议与队列

判机端只出站连接服务器，四个动作：

```
POST /judge/claim                       → 心跳注册 + 领取（404 = 队列空）
GET  /judge/submissions/{id}/cases/{ordinal}/{in|out}?judge=NAME → 取这条工单的用例
POST /judge/submissions/{id}/status     → compiling → running
POST /judge/submissions/{id}/result     → 判定 + 逐用例行
```

用例正文按「这条提交的第 N 条」取，不按用例的数据库 id 取，而且服务器会核对这条提交确实
派给了报上来的那台判机。老写法（`/judge/cases/{id}`）等于给判机一个可以顺着 1、2、3 枚举
**全站隐藏输入与答案**的把手——判机令牌一旦泄露（它曾在 `ps` 里），那种泄露没法回收。
现在拿到令牌的机器只能读到自己被派到的那几份文件。

判机每次心跳还会自报两件事，服务器照它们办事：

- **`capabilities`（这一版代码会做什么）**：`options` / `checker` / `interactor`。派单时
  照它筛——一台旧判机不认识工单里的 `options` 与判题器，派过去它会照自己那套硬编码编、
  按逐字节比较判，然后**正常回报成功**，于是页面上那句「C++14 · O2 关」「本题由 SPJ 判定」
  成了当着的谎。需要这些能力的工单因此不会派给没自报的机器，而是在队列里等一台判得了的。
  语言不在这一份里：判机没有某门语言的工具链时它自己会如实回一条判机故障，那是看得见的
  失败；把提交扣在队列里等一台不存在的机器是更坏的失败。
- **`jailed`（此刻会不会把一次运行关进牢房）**：这是每次心跳重报的当下状态，不是版本属性。
  它过去只写在启动日志的一行里；现在 `/judges` 有「隔离」一列，且**没有任何一台机器有牢房时
  页面顶部当面警告**——那种时候提交是在判机自己的身份下、在宿主文件系统上跑的。
  没报过的老判机显示「未报」，不显示成「确认没有」。

判完还会回报**它实际用的口径**（`toolchain`，如 `C++14 · O2 关`、`python 3.14`）。
提交详情页与列表显示的是这一份，不是提交表单里选的那份；判机没回报时页面写「未回报」。
选了版本却被一台旧判机按默认编了，差别只有动手编的那台机器知道。

服务器侧的规则：

- **领取是单条语句** `UPDATE … WHERE id=(SELECT … WHERE status='queued' LIMIT 1) RETURNING`，两台判机抢同一份提交时后者必然 0 行受影响；4 框并发抢 24 条实测零重复
- 状态迁移是 CAS：`UPDATE … WHERE id=? AND status=?`，`judge.Transition` 列出合法迁移并与 schema 的 `CHECK` 对齐
- 判机中途死掉 → 按 `started_at` 租约回收成 `abandoned` + `IE`；`RequeueAbandoned` 只允许把 abandoned 放回队尾，已成定局的提交不能被重新排队
- **分数不信任判机的算术**：`tallyResult` 按库里的用例权重重算；谎报 AC 但逐用例行里有非 AC → 降级成那个判定；消失的用例行也不能证明 AC；认不出的 verdict 字符串一律记 `IE`（判机故障不该算提交者的错）
- 判机拿不到结果时也必须回报 `IE`，不能让提交卡在 `compiling` 等租约

## 判机隔离（边界必须说清）

当前支持语言：**C / C++ / Python**（C/C++ 走 `g++ -x c++ -std=c++17 -O2 -w -static`，Python 见[Python 提交](#python-提交护栏装在解释器里边界还是牢房)）。命令一律是 argv 数组，绝不拼 shell 字符串。

Windows 本地判机（`runner_windows.go` + `runner.go`）：

- 内存上限用 Job Object 落实：`JOB_OBJECT_LIMIT_PROCESS_MEMORY` 管单进程，`JOB_OBJECT_LIMIT_JOB_MEMORY` 管整棵树（上限的 4 倍），实测 32 MB 上限下 `malloc(512MB)` 直接返回 `NULL`；无上限时如实报出峰值 526 MB
- **进程数上限** `JOB_OBJECT_LIMIT_ACTIVE_PROCESS`（提交默认 4，编译 16）：没有它，一个 `fork` 循环可以躲在单进程内存上限下面把机器的进程表和 CPU 吃光
- CPU 时间取进程退出状态里的 FILETIME，内存取 Job 的 `PeakProcessMemoryUsed`
- 超时用 wall-clock 兜底（`max(2×时限, 2s)`）并整树击杀 —— 只限 CPU 的话，一个 `sleep` 型程序能把判机槽位永久占死
- **环境变量一律不继承**：判题进程只看到 `PATH`/`SystemRoot`/`WINDIR` 与指向临时工作目录的 `TEMP`/`TMP`/`HOME`/`USERPROFILE`。fast-judge 自己的令牌、数据库路径、服务单元导出的任何秘密，`getenv` 都读不到
- 启动时把边界打印一次，避免有人在日常使用的机器上把判机当成沙箱
- **Windows 上内存超限通常表现为 `RE`（分配被拒）而不是 `MLE`**，Linux sandbox 才给得出明确的 MLE

**Windows 上仍未隔离：文件系统、网络、以及"能不能弹窗口到你的桌面"。** 判题程序就是以 fast-judge 那个用户的身份在跑，能读写该用户能读写的一切，`system("shutdown -s -t 3600")` 这类调用会真的被系统接受 —— Job Object 的 UI 限制在 Vista 之后就被 Windows 作废了，`shutdown.exe` 也不是靠 `ExitWindowsEx` 的句柄限制能拦的。Linux 上没有这个问题：判题沙盒已经把网络与文件系统这两道关上了（见下）。

| 你要的强度 | 做法 |
|-----------|------|
| 本机自测、只跑自己的题 | 现在这样就够 |
| 接受陌生人提交 | Linux 上开沙盒（默认就开），并给它一个专用账号或容器；**别在登录用的账号上跑 fast-judge**（Windows 上判机没有这层保护） |
| 生产 | 判机放 Linux 容器 + 开沙盒（`docker-compose.judge.yml` 已经把需要的 cap 加好了）；要连内核攻击面一起收，再叠 seccomp（尚未做，见[已知限制](#已知限制)） |

### 判题沙盒（`internal/jail`：一次运行一个牢房）

Linux 上每次判题运行都被关进一组命名空间，靠的是**判机 exec 自己**：Go 没法在 fork 与
exec 之间插东西，所以 `setrlimit`、`mount`、`chroot` 这些必须由子进程在 exec 提交程序
之前自己做完。牢房里：

| 面 | 手段 | 实测结果 |
|----|------|---------|
| 网络 | `CLONE_NEWNET` | 只剩一条 DOWN 的 lo；`connect(8.8.8.8:53)` 返回 `ENETUNREACH`。**阿里云元数据 `100.100.100.200` 一并废掉** |
| 目录 | `CLONE_NEWNS` + 把系统目录只读 bind + `chroot` 到这次运行的工作目录 | `/etc/passwd`、`/var`、别人的源码都不存在；`fopen("/etc/xxx","w")` 失败 |
| 进程 | `CLONE_NEWIPC`/`CLONE_NEWUTS` + `RLIMIT_NPROC` | fork 炸弹被内核掐住（实测 400 次 fork 在 8 的额度下被判 TLE 并整组杀掉） |
| 时间 | 判机墙上时钟 + 整组击杀，另有 `RLIMIT_CPU` 宽两秒兜底 | 死循环仍是 `TLE`，且给出实测值 |
| 内存 | 判机实测 `rusage` + `/proc` 轮询熔断，`RLIMIT_AS` 只留 512 MB 余量 | 吃 300 MB 而限 64 MB 仍是 **`MLE`**，不会被抢先打成 `RE` |
| 身份 | root 判机降到 `-run-as` 的 uid；非 root 判机走非特权 user namespace，最后落到一个**未映射**的 uid | 宿主看到的是 nobody，判机的库、令牌、别人的提交都读不到 |

`-sandbox=on` 是硬要求：启动时真建一次牢房，建不出来判机就**拒绝启动**（`systemctl status fast-judge` 会看到原因），不会悄悄按不隔离的路子重跑。
`-sandbox=auto`（默认）反过来：开不了就**不再尝试**，在启动日志与 `/judges` 上写明"未隔离"，判题照常。以前 auto 是"开不了也每条都试一次"，于是每台开不了命名空间的机器都会把每条工单判成 `IE`——那条已经修掉了。
牢房建不起来时判机报 `IE` 而不是 `RE`：内核不给权限，不该让学生去查自己的代码。

三个实测踩过的坑，改这块代码前先看：

- **自测的成败不能看退出码**。`unshare()` 被内核拒掉时 exec 根本没有发生，Go 把整条
  fork→unshare→exec 的失败报成 `fork/exec <路径>: permission denied`，退出码还是 0。
  只看退出码就会把"这台开不了牢房"记成"沙盒已启用"，判机于是边在日志里说谎、边把每条
  提交判成 `IE`（阿里云 ECS 上撞到的正是这条）。自测认的是**判定**：任何一次 `IE` 都是失败。
  同理，`SetSandbox` 换配置时必须把上一次自测的结论清掉——`probeUnavailable` 是"按这套
  配置这台机器开不了"的答案，留着它下一次自测根本不去建牢房，于是又在牢房外把 `/bin/true`
  跑成功、报"已启用"。
- **不能开 `CLONE_NEWPID`**。Go 是 fork 之后再 `unshare()` 的，而 `unshare(CLONE_NEWPID)`
  只把调用者的**子进程**放进新 pid 命名空间，被 exec 的程序自己还在原来那个；留着它
  拿不到好处，还会让被 exec 起来的 Go 程序（判机自己）在起线程时 `EINVAL`。
- **`RLIMIT_AS` 不能卡到判定线上**。卡紧之后超内存的申请直接 `ENOMEM` 崩掉，判定从
  `MLE` 变成 `RE`，等于用安全性换掉了判题口径。

判机容器要多给三个能力：`SYS_ADMIN` + `NET_ADMIN`（开 mount/network 命名空间）、
`SYS_PTRACE`（读降权子进程的 `/proc/<pid>/statm`，内存熔断靠它）。Docker **默认 seccomp
profile 不需要放开**，实测照跑。

### 系统调用过滤（seccomp 黑名单）

牢房建好、降完权、上限额之后，exec 学生程序之前最后一件事是装一层 seccomp-bpf
（`internal/jail/seccomp_linux.go`）：**黑名单**，命中就返回 `EPERM`。挡掉的是

- `socket` / `connect` / `bind` / `listen` / `send*` / `recv*` / `shutdown` / `socketpair` /
  `accept*` —— 断网本来靠 `CLONE_NEWNET`（命名空间里没有第二张网卡），这一层挡的是内核攻击面；
- `ptrace`、`process_vm_readv/writev` —— 「看着判机正在跑谁的哪道题」这条路；
- `mount` / `umount2` / `pivot_root` / `chroot` / `setns` / `unshare` —— 在牢房里再动挂载表或换一个牢房；
- `reboot` / `kexec_load` / `swapon` / `swapoff` / `bpf` / `userfaultfd`。

配上 `PR_SET_NO_NEW_PRIVS`（内核要求它与非特权时装过滤器结伴），并用
`SECCOMP_FILTER_FLAG_TSYNC` 一次装到**所有线程**——Go 与 Python 都是多线程的，`prctl`
那条路只管当前线程，"看着装了其实没装"是最坏的一种失败。

三个决定都是有依据的，改的时候别绕过去：

- **为什么返回 `EPERM` 而不是 `KILL`**：`SECCOMP_RET_KILL_THREAD` 只杀一个线程，其余的
  永远等（实测 Go/Python 都表现为挂住不返回，判机只能靠墙上时钟收，那条判定不可用）；
  `KILL_PROCESS` 又把"学生调了一个被挡的调用"变成一条没有原因的信号死。EPERM 让调用失败、
  程序自己报错，学生看到的是一句能读懂的 `PermissionError`。
- **为什么不是白名单**：实测白名单要 150 条以上才装得下 g++ 与 CPython（换发行版就变），
  装漏一个就是把"这台判机判不了题"变成常态；而要能编译就必须放行 `execve`/`clone3`/`wait4`，
  于是它连"不许起进程"这件本该由它解决的问题都没解决。
- **为什么装在 `LookPath` 之后**：牢房自己还要用 `unshare`/`mount`/`chroot` 这些被挡的调用，
  早装一步就死在建牢房半路上（装不上时按"牢房没建起来"出去，判机报判机故障，不让学生背）。

`internal/jail/seccomp_linux_test.go` 里有一条测试专门盯着 cBPF 的跳转方向：跳转写反**不会
报错**——内核照样收下过滤器，程序照跑，只是什么都没挡。实测就是这样让 `socket()` 与
`ptrace()` 在"装了 seccomp 的牢房"里双双成功。所以那条测试不测"装上了没有"，而是顺着指令流
走一遍，检查"号命中"这条路真的走到 `RET ERRNO`；`TestJailHasNoNetwork` 再在真牢房里断言
`socket=-1 errno=1`、`ptrace=-1 errno=1`。

`/proc` 现在以 `hidepid=2` 挂进牢房：只换新的 `/proc` 挡不住读
`/proc/<别人的 pid>/cmdline`、`environ`，而那些里能看到判机在执行谁的哪道题。

### 落地检查：牢房到底开起来了没有（`scripts/judge-isolation.sh`）

「代码里有沙盒」与「这台机器上真的在开沙盒」是两件事。Ubuntu 24.04 起
`kernel.apparmor_restrict_unprivileged_userns=1`，非 root 的判机 `unshare(CLONE_NEWUSER)`
会被内核直接拒掉——判机于是照常判题，只是**没有隔离**：提交在判机自己的身份下、在宿主
文件系统上跑。这件事只在启动日志里占一行，没人盯日志就等于没人知道。

```bash
sudo bash scripts/judge-isolation.sh --check      # 只看，不动任何东西
```

它真跑一次 `unshare -Urm true`（按判机那个身份），报四件事：运行身份、user namespace
开不开得了、判机令牌有没有写在命令行上、`EnvironmentFile` 的权限。`/judges` 网页上现在
也直接写着每台机器的「隔离」状态，没有一台有牢房时页面顶部红字警告。

三条修好的路，每条走完都**当场重新实测**一次，不接受"配好了"的推断：

- `--root`：把判机改成 root 跑。这是非特权 userns 被拦的机器上牢房开得起来的那条路——
  学生程序仍然在降权之后才被 exec（`internal/jail` 的 `drop()`），拿到的是 nobody/未映射
  的 uid、无网络、看不到宿主文件系统。
- `--apparmor`：保持非 root，给判机那个可执行文件装一份允许 userns 的 profile。这条路
  对内核与 AppArmor 版本敏感，所以脚本自己会验：装完实测不通就报出来并给撤掉的命令，
  不留半套配置。
- `--rotate-token`：换判机令牌，并用一个 systemd drop-in 把 `-token` 从 `ExecStart` 里
  彻底去掉。**令牌写在命令行上等于发给整台机器**（`/proc/<pid>/cmdline` 是 0444），
  而 systemd 会先展开 `ExecStart` 里的 `$VAR` 再 exec，所以 0600 的 `EnvironmentFile`
  也白设。判机二进制的 `-token` 默认值本来就是那个环境变量；新版判机在 Linux 上
  **拒绝**以命令行令牌启动。

⚠️ 部署顺序：新版判机看到 `-token` 在命令行上就不启动。所以上新二进制时要么先把
`ExecStart` 里的 `-token` 去掉（`--rotate-token` 就是干这个的），要么判机会直接停掉。
两个服务的令牌来自同一个 `EnvironmentFile`，换令牌要**一起重启**，不然队列会卡在 401。

### 判机容器化（`Dockerfile.judge` + `docker-compose.judge.yml`）

把提交代码关进容器，是现在最省事的一层真隔离：Docker Desktop 的容器跑在轻量 VM 里，
判题程序连你登录用的账号都不是同一个。

```bash
# 1. 服务器照旧在宿主上跑
./dist/fast-oj.exe -addr 127.0.0.1:18080 -data data -admin-token ADM -judge-token JDG

# 2. 交叉编译 + 构建镜像 + 起容器（只需出站连接，没暴露任何端口）
FASTOJ_JUDGE_TOKEN=JDG bash scripts/judge.docker.sh          # 本地已有镜像时直接复用
REBUILD=1 FASTOJ_JUDGE_TOKEN=JDG bash scripts/judge.docker.sh  # 装了新工具链时强制重建
SOURCE=1 FASTOJ_JUDGE_TOKEN=JDG bash scripts/judge.docker.sh   # 本机没有 Go：把编译挪进容器
```

`docker build` 每次都要向 Docker Hub 取 `FROM` 的元数据，网络不通就整镜像失败；脚本
因此带了一条离线回退：把新编译的二进制 `docker cp` 进临时容器再 `docker commit`
（commit 时显式写回 `ENTRYPOINT`，否则会把临时容器的 `sleep` 提交进去）。等价于只重跑
那一层 COPY，工具链没变时完全够用。

两份 Dockerfile 的分工，别混用：

| 文件 | 怎么出二进制 | 需要什么 |
|------|--------------|----------|
| `Dockerfile.judge` | 本机先交叉编译，`COPY dist/linux_amd64/fast-judge` | 本机有 Go；`dist/linux_amd64/` 里**要有那个文件**（空目录会让构建在 COPY 那一步失败） |
| `Dockerfile.judge.source` | 容器里 `golang` 阶段编（`SOURCE=1` 走这条） | 构建上下文里有 `go.mod`、`go.sum`、`cmd/`、`internal/`；一次网络取模块（默认 `GOPROXY=https://goproxy.cn,direct`） |

`.dockerignore` 因此**不能用 `*` 减白名单**：那样上下文里就没有模块文件，后一份在
`COPY go.mod` / `go mod tidy` 那一步直接撞死。它现在是逐条列的黑名单——挡的是
`data/`（几十 MB 演示库与用例）、`.git/`、`.tmp/`、`*.exe` 这些，源码留在上下文里。

容器里跑的约束（下面这套已在 Docker Desktop 29.7.2 / linux 引擎上实测）：

| 手段 | 挡住什么 |
|------|----------|
| `cap_drop ALL` + `cap_add SETUID,SETGID,KILL,SYS_ADMIN,NET_ADMIN,SYS_PTRACE`，`no-new-privileges` | 只保留"把提交降权""杀掉它""开牢房的那三个能力"，其余一律没有 |
| `-run-as 65534:65534`（判机 root 起步，提交降到 nobody） | 提交读不到判机进程的环境（`/proc/1/environ`）与判机令牌，跨 uid 之后内核直接拒绝 |
| `read_only` 根文件系统 + `/work` tmpfs（512 MiB，**必须带 `exec`**） | 改不了镜像里的任何东西；写盘有额度。Docker 给 `--tmpfs` 默认挂 `noexec`，而编译产物就在 `/work`，漏写 `exec` 时判题全部 `IE` |
| `mem_limit` / `memswap_limit`（不给 swap） | 超内存被 cgroup 拦下，实测 512 MiB 的提交报出 524940 KB 并判 `MLE` |
| `pids_limit 256` + `--ulimit nproc=128` | fork 炸弹 |
| `--ulimit fsize=64MiB`、`core=0`、`cpu=120` | 写满磁盘、留下 core 文件、CPU 兜底 |
| 判机侧 `Setpgid` + 整组击杀 | 超时的进程树不会变成孤儿继续吃 CPU |

判机以前不发 rlimit 给子进程：Go 在 Linux 上没有"spawn 时带 rlimit"的通道
（`SysProcAttr.Rlimits` 只有 BSD 有），而绕道 shell 的 `ulimit` 会让判定结果依赖镜像里
装的是 dash 还是 bash。现在这一条由**牢房**解决：jailer 在 `exec` 提交程序之前自己
`setrlimit`，所以内核层面有硬顶，而判定仍然来自判机的**测量**（CPU 取 `wait4` 的
rusage，内存取 `ru_maxrss`），Linux 容器的 `MLE` 因此比 Windows 的 `RE` 更准确。
cgroup 仍然是最外面那层（`mem_limit`/`pids_limit`），牢房是它里面一层。

判定口径（`judge.Run`）：

- **实测 CPU 时间超过本题时限就是 `TLE`**，即使程序自己正常退出了。原来只有 wall-clock
  到点才给 TLE，一个跑掉 1038ms 却 `return 0` 的程序会被判成 AC。
- 每个测试点允许多跑 **50 ms** 才被砍（`wall = 时限 + 50ms`，最小 250 ms 兜住进程创建）。
  这 50 ms 不是为了放宽时限，是为了让程序**跑完到能被测量**：1000ms 的题，
  1050 / 1038 / 1001ms 都算超时，各自报出自己的数字。
- 被中途杀掉的运行只能给出**下界**，网页与文本视图给它们加 `>` 前缀：
  `>1050ms`、`>289.00M`；自然跑完的运行仍然显示精确值。
- 内存不再等容器 OOM：判机每 20 ms 轮询一次峰值，超过**本题上限 + 16 MB** 立刻整组击杀
  并判 `MLE`（Linux 读 `/proc/<pid>/statm`，Windows 读 Job 的峰值）。实测 256 MB 上限的题，
  一个申请 512 MB 的程序在 289 MB 处被砍，报 `>289.00M`。

两个坑是实测踩出来的，都进了代码与测试：

- **`cap_add` 里少了 `KILL`**：降权之后判机（uid 0）给 uid 65534 的子进程发 SIGKILL 会
  `EPERM`。表现是超时的程序杀不掉、判机卡在输出管道上、整条队列停摆（要等容器
  `--ulimit cpu` 收尸）。现在 `Kill` 会把错误带出来，并且最多再等 5 秒就带着
  `TLE` 与原因返回，绝不无限占着判机槽位；回归用例是 `TestDroppedSubmissionStillTimesOut`
  （需要 root 判机，用 `FASTOJ_TEST_RUN_AS_UID=65534` 打开）。
- **`internal: true` 网络不能用**：它把 `host.docker.internal` 一起挡了
  （`dial tcp 192.168.65.254:18080: network is unreachable`），判机领不到工单。所以
  compose 里默认不开，**提交程序的出口网络目前没有被限制**——要单独掐掉，得给每次运行
  开一个无网络的命名空间（容器内 root + `CAP_NET_ADMIN` + `unshare -n`，再降权），
  这条归到外部 sandbox 那一期。挡住的关键面仍然是：宿主的文件系统、进程与关机权限。

输出：每路最多 1 MiB，超出即按 `WA` 判（已经打印出来的内容不可能再对上答案）。

## 性能

`go test -run XXX -bench . ./internal/api/` 与 `TestReadPathP99Budget`，数据规模 200 道题 / 每道 5 个用例 / 500 条提交，Windows 回环，i7-10700KF：

| 路径 | 每次请求 | p50 | p99 |
|------|----------|-----|-----|
| `/healthz` | 0.16 ms | <1 ms | 1.0 ms |
| `/problems?limit=50` | 0.86 ms | 1.0 ms | 2.2 ms |
| `/problems/{pid}`（含 Markdown 渲染） | 0.55 ms | 1.0 ms | 1.5 ms |
| `/submissions?limit=50` | 0.62 ms | 1.0 ms | 1.7 ms |
| `/rank` | 1.15 ms | 1.0 ms | 2.0 ms |

端到端 p50/p99 被 Windows 约 1 ms 的计时粒度顶住，所以看起来都 ≥1 ms；真正的工作量在"每次请求"那一列。

支撑这些数字的取舍：

- 列表一律游标分页（`WHERE id > ?`），不用 `OFFSET`，深页和第一页同价
- 列表查询不取 `source` / `detail` 大字段，只有单条且有权查看时才二次取回
- 待判队列走 `status='queued'` 部分索引
- 一次查询取回整页的用例数/通过数，不做 N+1
- WAL + 预编译语句 + 无 ORM 运行时
- 访问日志默认只记失败与 >50 ms 的请求，日志不吃掉延迟

已知会先劣化的地方：`/rank` 用相关子查询按用户聚合，用户数上千后需要改成物化计数列。

### 浏览器侧的账（F12 限速 3G）

后端 1 ms 级别不代表页面快。Chrome 的 Fast 3G 是 1.6 Mbps（≈200 KB/s）+ 150 ms RTT，
在这个档位下首字节 14 ms、整页 P99 却要 2.3 s——差的那部分是**下载量**：

| 项目 | 改前 | 改后 |
|------|------|------|
| 页面 HTML | 3–11 KB 原样发送 | gzip 后 1.5–2 KB（`/submissions` 10.8 KB → 1.55 KB） |
| `style.css` + `math.js` | 5 KB + 0.9 KB，`max-age=300` | gzip + `?v=<内容哈希>` + `immutable` 一年缓存 |
| KaTeX（CSS 23 KB + JS 275 KB + 字体 100–180 KB） | **每一页都从 CDN 拉** | 只有页面上真的存在公式节点时才拉 |

所以现在的规则是：`/problems`、`/submissions`、`/rank`、登录注册这些没有公式的页面，
一次外部请求都不发（实测网络面板只剩本站两个资源）；只有题面、写了公式的页脚/首页语
那类页面才付 KaTeX 的钱。加载逻辑在 `static/math.js`：模板里不留任何 CDN 标签，由脚本
发现 `span.math` 之后再注入 CSS 与 JS，CDN 不可达时原始 TeX 仍然可读。

还要再快可以做两件事：把 KaTeX 与其字体一并嵌进二进制（离线可用，省掉到第三方
的 DNS + TLS 握手，代价是二进制大约再胖 1.5 MB），以及把关键 CSS 内联进 HTML
（省一个 RTT）。

## 已知限制与后续

| 事项 | 现状 |
|------|------|
| 语言 | C / C++ / Python（见 [Python 提交](#python-提交护栏装在解释器里边界还是牢房)）。Python 的时限原样算、内存下限 32MB（64MB 的题照常收）、只在牢房开着的判机上收；`pypy` 之类的加速解释器没有，Java/Go 等仍未做 |
| 判题方式 | SPJ 判题器与交互题已做（见[判题方式](#判题方式普通比较--spj-判题器--交互题)），并由判机自报能力把关派单：没自报 `checker`/`interactor`/`options` 的机器领不到对应工单。仍**没有**：一条"这些题现在没人能判"的显式提示——队列里的提交只会显示「等待判题」，要去看 `/judges` 才知道是哪台机器掉队；判题器只能用判机有的工具链（`c`/`cpp`/`python`）；多条用例同时失败时只留**第一条**的评语；交互器读不到选手的转写文件（那是对话结束后才写的，对话本身走 stdin/stdout） |
| 判机隔离 | Linux 上每次运行都有命名空间牢房（无网络、看不到宿主目录、内核 rlimit 兜 CPU/内存/进程数）+ 一层 seccomp **黑名单**（`socket` 全家、`ptrace`/`process_vm_*`、`mount`/`unshare`/`setns`/`bpf`/`kexec` 等一律 EPERM，见[系统调用过滤](#系统调用过滤seccomp-黑名单)），root 与非 root 两种部署都能开；容器再套一层。仍**没有**：系统调用**白名单**（实测装不下 g++ 与 CPython，且要能编译就必须放行 `execve`/`clone3`/`wait4`，所以牢房里仍能起子进程）、pid 命名空间（需要 jailer 多 fork 一层，代价是退出码要自己传回来、内存轮询读的是 jailer 的 RSS，见[判题沙盒](#判题沙盒-internaljail一次运行一个牢房)）、Windows 上的任何文件/网络隔离（平台没有这套机制，`-sandbox=on` 会直接拒绝启动） |
| 账号 | 注册可关；**邮箱验证已做**（`/admin/site` 的第六个开关 + 图形化 SMTP 配置 + 发送测试邮件），未验证的账号能读能登录，但不能提交代码与参加比赛，验证链接一次有效、可在设置页重发。仍**没有**：「忘记密码」重置链接（忘了密码还是要管理员改库）、改邮箱入口（改了就得由管理员重发验证，因为旧邮箱收到的那条链接会被拒绝）、把验证做成"没验证连登录都不行"的更严模式 |
| 工单 | 已做（五类、四状态、私密、流水、处理人角标）。仍**没有**：新工单的邮件/推送提醒、按人分派与 SLA、附件上传（正文能写 Markdown，贴图得靠外链） |
| 比赛 | 已做（限时、加入码私有、队伍、OI/IOI/ACM 三种赛制独立榜、封榜）。OI 比赛中不出榜。仍**没有**：虚拟排名（参赛者不插进别人的榜）、比赛中改时限或换数据后对历史提交的重算、队长踢人/转让队长的完整 UI、比赛内单独的时限配置（用题目自己的时限）；时间全站按服务器时区，没有用户时区 |
| 升级 0015 | 老比赛里 `mode='oi'` 的**算法口径变了**（0013 那版算的其实是 IOI 的最高分）。数据不迁移：表结构只是多认一个 `'ioi'`，历史 `oi` 比赛从这次起按「最后一次提交、同分同名次、赛中不出榜」算，主办方要复核老比赛的赛制选择 |
| 比赛封榜 | 结束**不自动放榜**，要主办方手动勾「榜单公示」——忘了关是泄题，多一次点击不会 |
| 统计 | 排行榜只有「按去重 AC 题数」，无难度、标签、通过率排序 |
| 安全与审计 | 已做（0027 `audit` 只追加表 + `/admin/audit`，`ip.manage` 可看）：**特权动作**入库——授予/撤销能力、改角色、封号与解禁、注销、封与解 IP、站点设置保存、判题器存取、删用例与清空、删题、删比赛、移下题目、工单改状态与删除，判机协议那一路的**被拒鉴权**与**领单/回报**，以及**权限确认失败**（`step_up.denied`：拿着能改权限的会话却连着五次答不出密码，见[身份再确认](#改权限之前的身份再确认2-分钟)）。仍**只有 stderr** 的：提交与建题/改题的普通写路径、登录与注册、封禁**命中**的每一条被拒请求（一条一行会变成攻击者可控的写放大，只看内存流量表）、删帖删评论删动态这类用户自己的内容操作。审计表**没有**保留期与归档：只追加意味着它会一直长，真要长期跑还得配轮转 |
| 防作弊 | 无代码查重。登录/注册/发动态/提交/建题都有速率限制（见[参数](#参数)：提交与建题按人算，`-submit-per-minute` 默认 10），比赛内的提交同样计入；注册到第二个号、登录错到第 3 次起要等完人机验证那几秒**并且真的点一下那个格子**（点法是一次 `POST /verify`，服务端只在时间走完且请求像浏览器时盖章，见[人机验证窗](#人机验证窗观感是演给人看的等待是强制的)）。没有的是"同一份代码换个变量名再交"的查重 |
| 附件与图片 | 题面不能贴图（外链可以），无附件上传 |
| 静态资源 | 已按内容哈希加 `immutable` 一年缓存；模板与样式仍内嵌在二进制里，改样式要重新编译并重启 |
